# 建材彙整 · Matboard

上傳 SketchUp `.skp` 專案模型，網站直接解析檔案，擷取每個面的**材質、位置與尺寸**，
在 3D 預覽中點選任一牆面／地板／屋頂，即顯示該區塊的材質名稱與長、寬、面積。

**不需要在瀏覽網站的電腦上安裝 SketchUp** —— 解析在伺服器端完成。

```
使用者上傳 .skp
      │
      ▼
[ 轉檔器 skp2web ]  Python + ctypes → SketchUpAPI.dll
      │   遍歷群組／元件、累積座標變換、解析材質繼承
      │   合併同平面相鄰面 → 區塊(region)、依朝向量測長寬
      ▼
model.json  +  mesh.bin  +  textures/*.png
      │
      ▼
[ 檢視器 ]  three.js：點選 → raycast → 逐頂點 regionId → 該區塊資料
```

## 為什麼是這個架構

`.skp` 是未公開的專有格式，**沒有可靠的開源 parser**。唯一穩定的讀取途徑是 SketchUp 的
C API（`SketchUpAPI.dll`）。本專案用 Python `ctypes` 直接呼叫它，因此：

- 不需要 C++ 編譯器，也不需要另外編譯任何原生模組；
- 這台機器上的 DLL 來自已安裝的 SketchUp 2022，開發即可直接使用。

## 需求

| 項目 | 說明 |
|---|---|
| Python | 3.11+ |
| Node.js | 18+（僅建置前端時需要） |
| SketchUpAPI.dll | 由已安裝的 SketchUp 自動尋找，或以 `MATBOARD_SU_DLL` 指定路徑 |

### 關於 SketchUpAPI.dll 的兩件要事

1. **版本上限。** DLL 讀不了「太新」的檔案。實測 SketchUp 2022 的 DLL 可以讀取
   檔案版本 23.1 的模型，所以並非嚴格卡在自己的版本，但終究有上限 —— 超過時會回報
   明確訊息而非默默失敗。要支援更新的版本，請到
   [developer.sketchup.com](https://developer.sketchup.com/) 下載官方 SketchUp SDK，
   把其中的 `SketchUpAPI.dll` 放到 `vendor/sketchup-sdk/`，或設定：

   ```bash
   set MATBOARD_SU_DLL=C:\path\to\sdk\SketchUpAPI.dll
   ```

2. **授權。** 目前直接使用 SketchUp 應用程式安裝目錄中的 DLL，這在本機開發沒有問題；
   若要**部署到對外伺服器**，應改用官方 SDK 的可轉散布版本，並確認其授權條款。

## 安裝

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
cd web && npm install
```

## 執行

平常使用只要打開 **http://127.0.0.1:8000** 即可 —— 伺服器已設定為登入 Windows 後
30 秒自動在背景啟動（工作排程器，工作名稱 `Matboard 建材彙整伺服器`）。

| 需求 | 做法 |
|---|---|
| 手動啟動 | 雙擊 `開啟建材彙整.cmd`（會啟動並開啟瀏覽器） |
| 手動停止 | 雙擊 `停止建材彙整.cmd` |
| 查看自動啟動狀態 | `powershell -File tools\install-autostart.ps1 -Status` |
| 取消自動啟動 | `powershell -File tools\install-autostart.ps1 -Remove` |
| 重新設定自動啟動 | `powershell -File tools\install-autostart.ps1` |

伺服器背景執行、無視窗，約佔 60 MB 記憶體。啟動需約 40 秒，因為 `.venv` 位於網路
磁碟，Python 與相依套件都得透過 SMB 載入；自動啟動時這段時間在背景進行，不會被察覺。
若要縮短，把 `.venv` 移到本機磁碟即可。

記錄檔在 `logs\server.out.log` 與 `logs\server.err.log`。

### 開發

改動**轉檔程式碼後必須重啟伺服器**，否則新上傳的模型仍走舊邏輯：

```bash
.venv\Scripts\python.exe -m uvicorn server.app:app --reload --port 8000
```

前端開發伺服器（`/api` 會自動代理到 8000）：

```bash
cd web && npm run dev
```

要單一程序執行，先 `cd web && npm run build`，後端會自動把 `web/dist` 掛在 `/`。

### 只用命令列轉檔

```bash
.venv\Scripts\python.exe -m skp2web model.skp -o out\
```

會輸出 `out/model.json`、`out/mesh.bin`、`out/textures/`，並在終端印出建材彙整表。
加 `--include-hidden` 可納入關閉圖層上的物件（預設排除，讓數量與模型可見狀態一致）。

## 檢視器操作

沿用 SketchUp 的導覽習慣：

| 操作 | 動作 |
|---|---|
| 中鍵拖曳 | 旋轉 |
| Shift + 中鍵拖曳 | 平移 |
| 滾輪 | 縮放（往游標位置，非畫面中心） |
| Shift + Z | 顯示全部（Zoom Extents） |
| 左鍵點擊 | 選取面 |
| 右上角「水平剖面」 | 由上往下剖切，取出室內表面 |

左鍵拖曳與 Shift + 左鍵拖曳分別等同旋轉與平移。SketchUp 的左鍵是留給工具的，這裡保留
是因為筆電觸控板沒有中鍵，否則將完全無法旋轉；因為選取要求指標位移不超過 4px，
兩者不衝突。右鍵拖曳也可平移。

**室內表面一定要開剖面才點得到。** 樓板、天花與室內牆被不透明的屋頂與外牆包住，
射線只會打中最前面的那一層 —— 實測室內橡木地板（91.77 m²）在剖面關閉時，整個
畫面沒有任何一點選得到它。剖面同時作用於顯示與選取：被剖掉的部分不會擋住點選
（three.js 的 raycaster 本身不理會 clipping plane，這是額外處理的）。

## 擷取到什麼

每個**區塊（region）**包含：

- 材質名稱、顏色、透明度、貼圖與**貼圖單元實際尺寸**
- 表面分類：牆面／地板／天花／屋頂斜面／地坪景觀
- **長、寬**（依朝向採用不同量法，見下）與**實際表面積**（開口已扣除）
- 所屬群組／元件名稱、路徑、Tag
- 模型自身的 Attribute Dictionary（例如 `BIM_Data`、`Material_Specification`）原樣帶出

### 尺寸是怎麼量的

**量的是這個面實際的輪廓，不套任何外接框。** 先把區塊的真實邊界追出來
（丟掉被兩個面共用的內部邊，再把剩下的串成環），接著把共線點合併掉
（SketchUp 的一個矩形常常有五、六個頂點，因為其他幾何把它的邊切開了），
最後依形狀決定怎麼報：

| 輪廓形狀 | 報什麼 |
|---|---|
| **矩形** | 它自己的兩個邊長。牆面依立面習慣排成寬 × 高；斜屋頂排成沿屋脊 × 沿坡 |
| **三角形** | 三個邊長，外加最長邊與其對應高 |
| **其他多邊形** | 每一段邊長，另附整體範圍並明確標示「（範圍）」 |

轉了角度的樓板一樣量它自己的邊 —— 6 × 4 m 的板轉 30° 仍報 6.00 與 4.00，
而不是軸對齊外框的 8.2 × 7.5。

**面積永遠是三角形實算的表面積**，與上面的形狀判斷完全無關，所以開口與不規則
輪廓都正確。`solidRatio` = 面積 ÷ 輪廓面積，小於 1 表示這個面有開口
（例如帶窗的牆：實際 13.20 m² ÷ 完整輪廓 16.79 m² = 0.786），介面會標示。

### 面的合併

SketchUp 中一面牆常被邊線切成好幾個面。**同容器、同材質、同平面且共邊**的面會被
合併成單一區塊，所以點任何一小片都會回報整面牆。跨群組不合併，避免把相鄰但無關的
元件併在一起。

## 排除非建材

模型裡常有不是建材的東西：玻璃後方用來製造「暗室」效果的襯底量體、草地、水池、
概念植栽。它們會讓彙整表灌水（參考模型中，僅「室內陰影」一項就佔 484 m²、8.5%）。

彙整表每一列都有核取方塊，**取消勾選即可把該材質排除在合計之外**，合計與
「依表面類型」都會重算，CSV 也會帶「計入」欄；該材質在 3D 中仍可點選查詢。
選擇以專案為單位記在瀏覽器 `localStorage`，重新載入後保留。

材質名稱下方會顯示模型自己記的類別（取自屬性字典的 `Category`，例如
`Interior visual backing`、`Exterior wall finish`），作為判斷依據。

## 重疊面偵測

用實心量體組出來的模型有大量被埋沒的表面：鋪面壓在草地上時，草地的頂面與鋪面的
底面都是真實存在的面，位置完全重合，兩個都會被算進去，而兩個都看不見。
參考模型中這佔了全部表面積的 **63.0%**。

轉檔時會把所有面依平面分組，再以三角形對三角形做 Sutherland–Hodgman 裁剪，
求出**精確**的共用面積（不是估算）。分成兩類，扣除方式不同：

| 類型 | 意義 | 扣除 |
|---|---|---|
| **量體貼合**（法線相反） | 兩個量體面對面接觸 | **兩側都扣** —— 兩個面都被埋住 |
| **幾何重複**（法線同向） | 同一個面被畫了兩次 | **扣一次** —— 還有一份看得見 |

彙整表提供「全部面／扣除重疊」切換，選取面板會列出這一面被誰覆蓋、各佔多少。
CSV 兩種都含 `被埋沒`、`扣除重疊`、`重疊對象` 欄位。

## 匯出

| 格式 | 內容 |
|---|---|
| **PDF (A4)** | 一頁式報表：材質明細、表面類型分佈、判讀說明；抬頭會寫明計算基準與已排除的材質 |
| 彙整表 CSV | 各材質總面積、材質類別、計入與否、依表面類型拆分 |
| 明細 CSV | 逐區塊：形狀、各邊長、面積、被埋沒面積、重疊對象、中心座標 |

PDF 在**伺服器端**以 reportlab 產生（`server/report.py`），不是在瀏覽器裡。報表是中文的，
前端產生就得把 CJK 字型打包進 bundle，每次載入多背好幾 MB；伺服器端則直接用系統字型
（Microsoft JhengHei，退而求其次會找微軟雅黑／細明體／新宋體／標楷體），且只嵌入實際
用到的字符。

三種匯出都會套用當下的排除設定與「全部面／扣除重疊」選擇，PDF 另外把這個基準印在
抬頭上 —— 沒寫明基準的估算表，事後沒有人能判讀。

偵測本身很快（參考模型 890 個區塊約 0.24 秒），因為配對只在同一平面分組內進行。

### 薄板的背面

樓板畫成一塊板時上下兩面都存在，但面材只鋪一次。這兩面**不共面**（隔著板厚），
共面偵測抓不到，需要另一條規則。

判別靠**法線方向**而非厚度：薄板的兩片外皮法線**互相背離**，兩個量體貼合時則
**互相朝向**。厚度做不到這件事 —— 300 mm 的草皮板（底面埋在地下，該扣）與
300 mm 的牆（兩側都是真實飾面，不該扣）用厚度無法區分。

| 情況 | 處理 |
|---|---|
| **水平板**（樓板、屋面、地坪） | 面材只鋪上表面 → **扣除底面**，不論厚度 |
| **垂直且為透光材質**（玻璃） | 整片只買一次 → **扣一面**，不論厚度 |
| **垂直且不透光**（牆、門扇、板材） | 兩面都看得到 → **兩面都保留** |

三個前提：兩面必須**屬於同一個元件**（那是模型自己宣告它們是一個東西）、
**同材質**（不同材質代表兩種飾面，樓板上鋪木地板、下做油漆天花，兩者都要計）、
且薄板偵測在共面偵測**之後**執行並檢查剩餘未扣面積，因此同一塊面積不會被扣兩次。

實測參考模型：草皮板底面 1,224 m² 扣除、橡木地板底面扣除、玻璃只計一面，而
300 mm 磁磚牆的兩個 33 m² 面完整保留 —— 被誤扣的垂直面 0 個。

## 格柵以整片計算

木格柵在模型裡是二十根獨立的板條，逐面加總會得到「二十根棍子的表面積」（每一側、
每個端面），但規範與計價用的是**整片格柵在立面上的平方公尺**。參考模型中這是
13.17 m² 的棍子 vs 整片實際的 **6.88 m²**。

偵測是幾何性的，不依賴群組怎麼命名：

- 每個成員呈**條狀**（最長邊遠大於另外兩邊）
- 成員**同材質、互相平行、尺寸相近**
- 沿某一軸**等間距排列**
- **間距相對於成員本身很小**

最後一條是關鍵。一排柱子同樣是等間距的平行長條，差別在於它**不密集** —— 因此把
間距上限綁在成員寬度（≤ 6 倍）就能把柱列排除在外。單片板材、數量太少、間距不規則、
長度不一或材質混雜的情況也都不會被合併。

合併只影響**彙整數字**；3D 中每根板條仍可個別點選查詢，選取後會標示它屬於哪一片
格柵、整片面積是多少、以及逐面加總會是多少 —— 差異可被稽核，不是一個悄悄變掉的數字。

## 為什麼這些規則換個模型也成立

判定裡**沒有任何絕對長度**。以毫米寫成的規則只在它被寫出來時所對照的尺度成立，
換一個傢具細部或一份總體規劃就失效。因此所有條件都是三種形式之一：

| 形式 | 例子 |
|---|---|
| **方向** | 法線朝上／朝下、兩面互相背離或朝向 |
| **模型自己的宣告** | 兩面屬於同一元件、同材質、材質是否透光 |
| **比例與數量** | 條狀＝長邊 ≥ 4 × 次長邊、間距 ≤ 6 × 板寬、成員 ≥ 5 支、深度 ≤ 0.25 × 高 |

實測三個結構不同的模型（其中兩個從未用來調整參數）：格柵在 `Reference_01` 上自動
找出直立、水平、門扇板條共 3 組，在只有實心量體的 `sample.skp` 上正確回報 0 組；
被薄板規則扣除的垂直面分別為 3 / 5 / 6 個，逐筆檢查全部是玻璃，沒有任何一面牆被誤扣。

## 已知限制

- **不做完整可見性分析。** 偵測依賴「有另一個面與它重疊或背對」；完全埋在其他量體
  內部、又沒有共面或平行對應物的面仍會計入。
- **分類靠幾何 + 名稱關鍵字。** 水平朝上的面在幾何上無法區分樓板、平屋頂與地坪，
  因此會參考群組名稱／Tag／材質名稱。命名混亂的模型可能分類不準，但長寬面積不受影響。
- 目前一次只能轉一個檔；SDK 的 `SUInitialize`／`SUTerminate` 是行程全域狀態，
  伺服器已用 lock 序列化轉檔。
